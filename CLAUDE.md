# eurofins-post-registratie-create-mendrix-order

## Wat deze app doet
Netlify Function die inkomende webhooks (van Make.com / PWA) verwerkt en omzet naar
Mendrix-orders via de SOAP Custom Link API. Per entry wordt een transportorder aangemaakt
en worden eventuele foto's geüpload naar het Mendrix-dossier. Resultaten worden gelogd
naar Google Sheets.

## Stack
- TypeScript (ESM, strict)
- Netlify Functions (serverless, esbuild bundler)
- Vitest (unit tests)
- cross-env (Windows-compatibele env vars in dev)

## Commando's
```bash
# Installeer dependencies
npm install

# Lokale ontwikkelserver (Netlify CLI)
npm run dev

# Build (genereert version.generated.ts)
npm run build

# Tests
npm test

# Tests in watch-mode
npm run test:watch

# Type check
npm run typecheck
```

## Projectstructuur
```
src/mendrix/
  types.ts            → Alle domein- en API-types (OrderData, EntryPayload, Config, …)
  config.ts           → Laadt env vars, gooit bij ontbrekende waarden
  payload-mapper.ts   → WebhookPayload → OrderData mapping (entryToOrder)
  customlink-xml.ts   → Bouwt Mendrix Custom Link XML
  soap-client.ts      → SOAP envelope bouwen, verzenden, response parsen
  dossier-client.ts   → Foto's uploaden naar Mendrix dossier (REST API)
  order-service.ts    → Orkestreert SOAP + foto-upload + logging per entry
  sheets-logger.ts    → Logt resultaten naar Google Sheets
  ids.ts              → Mendrix client/product-ID mapping per ontvanger
  http-utils.ts       → HTTP hulpfuncties
  xml-utils.ts        → XML hulpfuncties
  version.generated.ts → Gegenereerd door scripts/generate-version.mjs (niet in repo)
  __tests__/          → Vitest unit tests per module

netlify/functions/    → Netlify Function handlers
scripts/              → Build- en hulpscripts
certs/                → TLS-certificaatketen (Sectigo)
netlify.toml          → Netlify build + redirect configuratie
```

## Kritieke regels
- `version.generated.ts` wordt gegenereerd door `pretest`/`build` — nooit handmatig aanpassen
- SOAP-calls gebruiken de Custom Link XML-structuur — raadpleeg bestaande XML-utils en tests bij wijzigingen
- Dependency injection in `order-service.ts` maakt de service testbaar zonder netwerkoproepen — handhaaf dit patroon
- Alle externe calls (SOAP, HTTP, dossier-upload) zitten in `try/catch` en retourneren een foutobject — nooit een onverwachte exception doorlaten naar de Netlify handler

## Karpathy Gedragsregels

### 1. Think Before Coding
**Don't assume. Don't hide confusion. Surface tradeoffs.**

Stel aannames expliciet. Bij meerdere interpretaties: presenteer ze — kies niet stilletjes.
Stop als iets onduidelijk is. Benoem wat onduidelijk is. Vraag het.

### 2. Simplicity First
**Minimum code that solves the problem. Nothing speculative.**

- Geen features voorbij wat gevraagd is
- Geen abstracties voor eenmalig gebruik
- Als 200 regels naar 50 kan: herschrijf

### 3. Surgical Changes
**Touch only what you must.**

Bij het aanpassen van bestaande code:
- Verbeter geen aangrenzende code, comments of formatting
- Verwijder imports/variabelen/functies die JOUW wijzigingen ongebruikt maken
- Match de bestaande stijl

### 4. Goal-Driven Execution
**Define success criteria. Loop until verified.**

Multi-stap taken: stel kort een plan op:
```
1. [Stap] → verify: [check]
2. [Stap] → verify: [check]
```

### 5. Tests na elke codewijziging
Bij elke codewijziging altijd controleren:
- Bestaande tests nog groen?
- Moeten bestaande tests aangepast worden?
- Zijn er tests die niet meer relevant zijn?
- Zijn er nieuwe tests nodig?

### 6. Foutafhandeling na elke codewijziging
Bij elke nieuwe functie of wijziging altijd zelf controleren (zonder dat de gebruiker dit hoeft te vragen):
- Alle externe aanroepen (SOAP, HTTP, bestands-I/O) zitten in een `try/catch`
- Functies die kunnen falen retourneren een foutobject of `null` — nooit een onverwachte exception naar de Netlify handler
- Foutmeldingen zijn informatief (bevatten context, geen ruwe stack traces naar de client)
- Nieuwe `catch`-blokken loggen met `console.error` of `console.warn` waar zinvol
